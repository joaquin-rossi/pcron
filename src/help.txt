TAB FORMAT:
  Each command is the delay before its next run, in seconds, followed by a
  script:

      # about once a minute, on average (a Poisson process)
      exp(1/60) $ echo hi >> /tmp/pcron.log

      # every 30 to 40 minutes of working hours
      stretch: uniform(30, 40) * 60 @ mon-fri 9-18 $ notify-send stretch

      # every 23 to 25 hours
      notes: 24*3600 + normal(0, 1800) $$
          cd ~/notes
          git commit -am "$(date)" && git push
      $$

  - The delay is made of numbers and distributions, with + - * / ^ and
    parentheses. A distribution is sampled at every run; its arguments must
    be constant and non-negative.
  - name: before the delay labels the command in the logs and in pcron list.
    Names are optional, and unique.
  - @ days hours makes the delay count only while that window is open, in
    local time (or PCRON_TZ): days like mon-fri or sat,sun, hours like 9-18
    or 9:30-12,14-18 (either can be left out).
  - $ ... runs the rest of the line; a $$ block ends at a line
    containing only $$.
  - NAME=value lines set environment variables for the commands below them,
    up to the end of the line; quotes keep the outer blanks, and $ is not
    expanded.
  - Some variables configure pcron instead of the script (which doesn't get
    them), also for the commands below them; times are in seconds and can
    use arithmetic, and empty means the default:

      PCRON_MIN_DELAY=1          every sampled delay is at least this
      PCRON_MAX_DELAY=31536000   and at most this (a year)
      PCRON_TIMEOUT=             SIGTERM after running this long (empty or
                                 0: no limit)
      PCRON_SHUTDOWN_TIMEOUT=60  SIGKILL this long after SIGTERM
      PCRON_TZ=                  time zone of the windows, like Europe/Madrid
                                 (empty: local)
      PCRON_ON_FAILURE=          a script to run when the script exits with
                                 an error, is killed or times out, or cannot
                                 start; it gets PCRON_NAME, PCRON_SCRIPT,
                                 PCRON_REASON (exit, signal, timeout or
                                 spawn), PCRON_EXIT, PCRON_SIGNAL and
                                 PCRON_OUTPUT (its last 20 lines)

  - Scripts run with $SHELL -c, where SHELL can be set in the tab
    (/bin/sh by default). A run starts even if the previous one is still
    going, like cron.
  - # starts a comment.

  Distributions:

      beta(alpha, beta)                    normal_inverse_gaussian(alpha, beta)
      cauchy(median, scale)                pareto(scale, shape)
      chi_squared(k)                       pert(min, max, mode, shape)
      exp(lambda)                          poisson(lambda)
      exp1()                               skew_normal(location, scale, shape)
      fisher_f(m, n)                       standard_normal()
      frechet(location, scale, shape)      standard_uniform()
      gamma(shape, scale)                  student_t(nu)
      gumbel(location, scale)              triangular(min, max, mode)
      inverse_gaussian(mean, shape)        uniform(min, max)
      log_normal(mu, sigma)                weibull(scale, shape)
      normal(mean, std_dev)

ENVIRONMENT:
  PCRON_TAB is the tab to use instead (with its .d directory too).
  PCRON_STATE is the file to keep the timers in instead (each tab needs its
  own).

SIGNALS:
  - SIGHUP reloads the tab: commands that did not change keep their timers,
    and an invalid tab is ignored.
  - SIGTERM and SIGINT stop the server: running scripts get SIGTERM, and
    are killed after PCRON_SHUTDOWN_TIMEOUT or when their PCRON_TIMEOUT runs
    out, whichever comes first; a second signal kills them right away.

FILES:
  $XDG_CONFIG_HOME/pcron/tab (or ~/.config/pcron/tab) is the tab, along with
  every *.tab in the tab.d/ next to it, in alphabetical order (either may be
  missing). Each file stands on its own: variables don't carry over from one
  to the next.
  $XDG_STATE_HOME/pcron/ (or ~/.local/state/pcron/, or $PCRON_STATE) keeps the
  next run of each command, so that a restart resumes them (and a missed one
  runs right away).
